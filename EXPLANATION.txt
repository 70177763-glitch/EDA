SECTION A – filters.py (Data Loading & Cleaning)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. pd.read_csv(path, low_memory=False)
   WHY: Standard Pandas function to load CSV files into a DataFrame.
        low_memory=False prevents dtype inference warnings on large files
        with 2.5M rows and mixed-type columns.

2. df.drop(columns=["Indicator_GId", "Subgroup_Val_GId", "Data_Denominator", "Footnote"])
   WHY: These four columns add no analytical value to the EDA:
        - Indicator_GId / Subgroup_Val_GId are internal UNAIDS database IDs.
        - Data_Denominator is >99% NaN (only 21,428 non-null out of 2.5M).
        - Footnote is >64% NaN and contains raw citation strings, not data.
        Dropping them reduces memory usage and keeps the DataFrame clean.

3. df.rename(columns={"Data value": "Data_Value", "Area ID": "Area_ID", ...})
   WHY: Column names with spaces (e.g. "Data value") require awkward bracket
        notation everywhere: df["Data value"]. Renaming to underscored names
        allows cleaner attribute-style access and prevents KeyErrors from
        accidental trailing spaces.

4. df.dropna(subset=["Data_Value"])
   WHY: 626,725 rows (25%) have no Data_Value. These rows carry no
        quantitative information for any chart or KPI. Dropping is safer than
        imputing health statistics, which could introduce bias.

5. df[df["Data_Value"] >= 0]
   WHY: The raw dataset contains negative Data_Value entries (e.g. –15,166).
        These are data artefacts from Spectrum modelling, not real measurements.
        Removing them prevents them from corrupting means, histograms, and
        min/max KPI cards.

6. df[col].str.strip().fillna("Unknown")
   WHY: String columns from UNAIDS sometimes have leading/trailing whitespace
        (e.g. "UNAIDS_Estimates_ " vs "UNAIDS_Estimates_") causing false
        duplicates in groupby operations. Stripping normalises them.
        fillna("Unknown") preserves rows while making absent data explicit.

7. pd.to_numeric(df[col], errors="coerce")
   WHY: After loading, some numeric columns may have stray strings.
        errors="coerce" replaces unparseable values with NaN instead of
        crashing, then we drop the resulting NaN rows.

8. df.reset_index(drop=True)
   WHY: After dropping rows, the integer index has gaps (e.g. 0, 1, 5, 8...).
        reset_index gives a clean 0-to-N index, which prevents off-by-one
        errors in iloc operations and produces cleaner debug output.

9. apply_filters() function
   WHY: All 8 sidebar filters feed into ONE function which returns ONE
        filtered DataFrame. Every chart then uses this same fdf.
        This guarantees the rubric requirement: "filters linked to ALL charts."
        Without centralisation, a filter might update chart A but not chart B.

SECTION B – charts.py (All 10 Charts + Bonus)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

CHART 1 – PIE CHART (Distribution of HIV Indicator Units)
----------------------------------------------------------
COLUMNS USED: Unit (categorical — "Rate", "Number", "Percent")
WHY THIS CHART: A pie chart is ideal for showing PROPORTIONAL COMPOSITION
  of a whole. Here it shows what percentage of all records use each unit
  type — Rate vs Number vs Percent. This instantly communicates whether
  the dataset is dominated by normalised rates or raw counts.
WHY THIS COLUMN: Unit type determines how data values should be interpreted.
  If 80% of records are Rates, aggregate averages are meaningful. If mixed,
  the analyst must filter by unit before any comparison.
KEY COMMANDS:
  df["Unit"].value_counts().head(6) → counts occurrences of each unit
  ax.pie(..., autopct="%1.1f%%")   → shows percentage on each wedge
  wedgeprops=dict(edgecolor=BG)    → adds thin border between slices for clarity

CHART 2 – HISTOGRAM (Distribution of HIV/AIDS Data Values)
-----------------------------------------------------------
COLUMNS USED: Data_Value (continuous numerical)
WHY THIS CHART: A histogram shows the FREQUENCY DISTRIBUTION of a numerical
  variable. It answers: "Are most measurements small rates near zero, or are
  there large absolute numbers pulling the distribution right?"
WHY THIS COLUMN: Data_Value is the primary measurement column. Understanding
  its distribution is the very first step of EDA — before any stratification
  by indicator, area, or time.
KEY COMMANDS:
  df["Data_Value"].quantile(0.99)  → cap at 99th percentile to exclude
                                     extreme outliers (e.g. global PLHIV count)
  sns.histplot(..., kde=True)      → adds Kernel Density Estimate over bars
  bins=40                          → 40 bins gives resolution for 2M+ records

CHART 3 – LINE CHART (Global HIV/AIDS Indicator Trends Over Time)
------------------------------------------------------------------
COLUMNS USED: Time_Period (x-axis, 1990–2024), Data_Value (y-axis, averaged)
WHY THIS CHART: A line chart is THE STANDARD for time-series data. It shows
  how the global average of all HIV/AIDS measurements has changed year over year.
WHY THESE COLUMNS: Time_Period is the temporal axis of the dataset. Averaging
  Data_Value across all indicators per year reveals macro-level trends:
  e.g., rising absolute counts through 1990s–2000s, then stabilising as ART
  expanded.
KEY COMMANDS:
  df.groupby("Time_Period")["Data_Value"].mean() → annual aggregation
  ax.fill_between(...)  → shaded area adds visual depth to the trend
  marker="o"            → circular markers highlight each annual data point

CHART 4 – BAR CHART (Top 10 Reporting Areas by Average Data Value)
-------------------------------------------------------------------
COLUMNS USED: Area (categorical), Data_Value (aggregated mean)
WHY THIS CHART: A horizontal bar chart is optimal for RANKING discrete
  categories with long text labels (country names). It immediately shows
  which areas have the highest average HIV/AIDS burden.
WHY THESE COLUMNS: Area captures geography (country or region). Sorting by
  average Data_Value surfaces the most heavily affected areas, which is the
  core policy question for any HIV/AIDS analysis.
KEY COMMANDS:
  df[df["Area_Level"] >= 2]   → excludes "All countries" aggregate to show
                                 individual country-level comparisons
  ax.barh(...)                → horizontal bars for long label readability
  ax.invert_yaxis()           → puts highest value at top

CHART 5 – SCATTER PLOT (HIV/AIDS Data Values Over Time by Unit Type)
---------------------------------------------------------------------
COLUMNS USED: Time_Period (x), Data_Value (y), Unit (color)
WHY THIS CHART: A scatter plot shows RELATIONSHIPS between two continuous
  variables and additionally uses color to encode a third categorical variable.
  It reveals whether Rate, Number, and Percent values occupy different value
  ranges and whether they trend differently over time.
WHY THESE COLUMNS: Plotting raw values against time shows data density (are
  some years reported more?), value scale by unit type, and any outlier years.
KEY COMMANDS:
  _sample(df, 30_000)        → random sample to prevent render slowdown
  quantile(0.95)             → caps extreme outliers for axis readability
  ax.scatter(..., alpha=0.4) → semi-transparent points prevent overplotting
                               in a dense 30K-point scatter

CHART 6 – BOX PLOT (Data Value Spread by Unit Type)
-----------------------------------------------------
COLUMNS USED: Unit (categorical x-axis), Data_Value (numerical y-axis)
WHY THIS CHART: A box plot shows MEDIAN, IQR (interquartile range), and
  OUTLIERS simultaneously. Comparing three boxes side by side reveals whether
  Rate, Number, and Percent measurements have different spreads and central
  tendencies.
WHY THESE COLUMNS: Unit type governs the scale of Data_Value. Rates are
  0–100, Numbers can reach millions. The box plot quantifies this scale
  difference and shows whether within-unit variance is large or small.
KEY COMMANDS:
  quantile(0.95)             → removes extreme outliers before plotting
  sns.boxplot(hue="Unit")    → automatic color grouping by unit
  flierprops                 → styles outlier dots in accent red

CHART 7 – HEATMAP (Correlation Between HIV/AIDS Indicators Over Time)
----------------------------------------------------------------------
COLUMNS USED: Indicator, Time_Period, Data_Value
WHY THIS CHART: A correlation heatmap shows ALL pairwise relationships at
  once. It reveals which HIV/AIDS indicators co-vary — e.g. do AIDS deaths
  correlate with new infections? Does ART coverage correlate with mortality?
WHY THESE COLUMNS: With 50 indicators, manually checking each pair would
  require 1,225 individual charts. The heatmap compresses this into one view.
  The top 8 indicators are selected by record count to ensure data density.
KEY COMMANDS:
  df.groupby(["Indicator","Time_Period"])["Data_Value"].mean().unstack()
                             → pivots to indicator×year matrix for correlation
  df[cols].corr()            → Pearson correlation matrix
  sns.heatmap(annot=True)    → prints r values inside each cell
  cmap="RdYlGn"              → red=negative, yellow=zero, green=positive
                               correlation (intuitive for health data)

CHART 8 – AREA CHART (Cumulative HIV/AIDS Data Records Over Time)
-----------------------------------------------------------------
COLUMNS USED: Time_Period (time), count of records (aggregated)
WHY THIS CHART: An area chart emphasises VOLUME and ACCUMULATION over time.
  The filled area makes growth in global reporting activity visually immediate.
WHY THIS COLUMN: Cumulative record count shows how HIV/AIDS global surveillance
  has expanded — each new year adds more countries, indicators, and subgroups.
  More records = better epidemiological coverage.
KEY COMMANDS:
  df.groupby("Time_Period").size()  → record count per year
  .cumsum()                         → running total
  ax.fill_between(...)              → fills area under the line with color
  ax.plot(...)                      → draws the line edge on top

CHART 9 – COUNT PLOT (Source Contribution Analysis)
----------------------------------------------------
COLUMNS USED: Source (categorical — 8 unique organisations)
WHY THIS CHART: A count plot is a bar chart where Seaborn automatically counts
  occurrences. It is the clearest way to show CATEGORICAL FREQUENCY.
WHY THIS COLUMN: The Source column identifies which organisation provided each
  data record. Showing record frequency by source reveals:
  (a) which sources dominate (UNAIDS Estimates), and
  (b) whether the dataset has diversity or is single-source.
  Data diversity affects how robust the analytical conclusions are.
KEY COMMANDS:
  Source_Short = Source.str[:30]    → truncates long source names for display
  sns.countplot(y="Source_Short")   → horizontal count bars for long labels
  order=order                       → sorts bars from most to least frequent

CHART 10 – VIOLIN PLOT (Data Value Distribution by Area Level)
---------------------------------------------------------------
COLUMNS USED: Area_Level (categorical: Global/Regional/National), Data_Value
WHY THIS CHART: A violin plot is a box plot enhanced with KERNEL DENSITY shape.
  It reveals whether the distribution is bimodal or skewed — information a
  box plot cannot show. Comparing Global vs Regional vs National level data
  shows how aggregation affects the value distribution.
WHY THESE COLUMNS: Area_Level stratifies the dataset into three geographic
  tiers. Global aggregates are single-point summaries; national data shows
  the true heterogeneity between countries. The violin plot quantifies this.
KEY COMMANDS:
  level_map = {1:"Global", 2:"Regional", 3:"National"}
                             → maps integer codes to readable labels
  _sample(df, 20_000)        → random sample for render performance
  sns.violinplot(inner="quartile")
                             → draws quartile lines inside the violin shape

BONUS – PAIR PLOT (HIV/AIDS Key Variables by Unit Type)
---------------------------------------------------------
COLUMNS USED: Time_Period, Data_Value, Area_Level + hue = Unit
WHY THIS CHART: A pair plot creates a GRID of scatter plots and KDE diagonal
  plots for all combinations of selected features. It provides a comprehensive
  multi-dimensional overview in one image — the most information-dense chart.
WHY THESE COLUMNS: Time_Period, Data_Value, and Area_Level are the three core
  structural variables of the dataset (when, what value, what geography).
  Coloring by Unit reveals whether Rate/Number/Percent cluster differently
  in this 3D space.
KEY COMMANDS:
  _sample(df, 5_000)                → small sample — pairplot is O(n²) in pairs
  sns.pairplot(hue="Unit")          → automatic color coding by unit type
  diag_kind="kde"                   → KDE on diagonal (smoother than histogram)
  plot_kws=dict(alpha=0.4, s=10)   → small, semi-transparent points for density

st.set_page_config(layout="wide")
  WHY: Wide layout uses the full browser width. With 10 charts in 5 rows of
       2 columns each, narrow layout would make charts tiny and unreadable.

@st.cache_data
  WHY: Caches the loaded DataFrame so Streamlit does not re-read the 2.5M-row
       CSV every time a filter changes. Without caching, each filter interaction
       would trigger a full disk read + clean cycle (~5–10 seconds). With caching,
       subsequent filter changes are near-instant.

st.session_state["reset"]
  WHY: Streamlit re-runs the entire script on every user interaction. Using
       session_state to track a "reset" flag is the correct Streamlit pattern
       for resetting all widgets to their default values simultaneously.

st.rerun()
  WHY: Forces an immediate full re-run after setting reset=True so all filter
       widgets re-render with default values before the user sees the page.

st.columns(2)
  WHY: Splits the page into 2 equal columns. Placing charts side by side uses
       horizontal screen space efficiently — standard dashboard grid layout.

st.pyplot(fig)
  WHY: Renders a Matplotlib/Seaborn figure inside Streamlit. This is the
       bridge between Python chart objects and the web interface.

st.expander()
  WHY: Wraps the pair plot (slow to render) and raw data table in collapsible
       sections. Users who don't need them won't wait for them to load on
       every page interaction.

st.markdown(..., unsafe_allow_html=True)
  WHY: Allows injecting custom HTML/CSS for the banner, KPI cards, section
       headers, and chart wrapper divs — visual elements that go beyond
       Streamlit's default widget styling.

matplotlib.use("Agg") in charts.py
  WHY: Streamlit runs as a web server process with no display monitor.
       "Agg" is a non-interactive backend that renders to in-memory buffers
       instead of a screen. Without this, Matplotlib would crash trying to
       open a GUI window in a headless server environment.

_sample(df, n) helper in charts.py
  WHY: The dataset has 2.5 million rows. Scatter plots, violin plots, and
       pair plots that try to render all rows would take 30–120 seconds and
       use gigabytes of memory. Random sampling preserves the statistical
       distribution shape while keeping render time under 2 seconds.
